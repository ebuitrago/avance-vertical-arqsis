La revisión abarcó las entregas de 6 de los 11 equipos. En la semana 14 se revisará qué respuesta da la API para cada uno de los dos requisitos funcionales y qué ocurre con los datos cuando el servicio rechaza una solicitud.

Qué se revisó

  • Alcance funcional. El equipo identifica dos requisitos funcionales (RF), justifica su prioridad y relaciona cada uno con las operaciones de datos que necesita.
  • Calidad verificable. Para cada requisito no funcional (RNF), el equipo indica el atributo de calidad, las condiciones de prueba, la métrica, el umbral y la semana de verificación.
  • Persistencia reproducible. El equipo documenta el esquema y los datos iniciales. Las pruebas cubren la escritura, la lectura desde otra conexión, la búsqueda de un ID inexistente y una restricción de integridad.

La revisión se basó en el código y los resultados de prueba de cada entrega. La persistencia quedó documentada cuando el resultado mostró que el registro guardado conservaba su identificador al recuperarse desde otra conexión.
