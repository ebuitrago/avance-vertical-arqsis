En el tercer corte de Arquitectura de Sistemas I, cada equipo elige dos requisitos funcionales de su proyecto y los implementa desde la interfaz hasta la base de datos. Ese recorrido completo es el corte vertical.

En la semana 15 se sigue cada operación desde la pantalla y se contrastan los resultados con las metas de calidad que definió el equipo.

Pudimos revisar las entregas de 6 de los 11 equipos. En la semana 14 revisaremos qué respuesta da la API para cada uno de los dos requisitos funcionales y qué ocurre con los datos cuando el servicio rechaza una solicitud.

Qué se revisó

  • Alcance funcional. Identificar los dos requisitos funcionales (RF), justificar su prioridad y vincular cada uno con las operaciones de datos que necesita.
  • Calidad verificable. Para cada requisito no funcional (RNF), indicar el atributo de calidad, las condiciones de prueba, la métrica, el umbral y la semana de verificación.
  • Persistencia reproducible. Documentar esquema y datos iniciales. Guardar un registro, recuperar el mismo ID desde otra conexión y comprobar ausencia e integridad.

Leímos el código y los resultados que entregó cada equipo. Para dar por documentada la persistencia, buscamos el mismo identificador en dos momentos de la prueba: cuando se guardó el registro y cuando se recuperó desde otra conexión.
